# 调试练习 Demo 使用说明

这个目录里是一个“学生成绩分析器”小 Demo，专门用来练习调试。
程序能正常运行，但里面故意埋了 **5 个 bug**，每个阶段 1 个。

## 一、文件说明

| 文件 | 用途 |
| --- | --- |
| `01_调试_demo.py` | 练习版，**先调试这个文件** |
| `02_调试_demo_修复版.py` | 参考答案，自己调完再看 |
| `README.md` | 本说明 |

## 二、运行方式

要求 Python 3.8+。在 `day05-调试技巧` 目录下执行：

```bash
# 一次运行全部 5 个阶段
python 01_调试_demo.py

# 只运行某一个阶段（调试异常时推荐这样跑）
python 01_调试_demo.py 1
python 01_调试_demo.py 2
python 01_调试_demo.py 3
python 01_调试_demo.py 4
python 01_调试_demo.py 5
```

> 建议：先直接运行一遍，看看每个阶段分别报什么错、输出什么奇怪的结果，
> 然后再打开调试器，带着问题去打断点。

## 四、5 个调试任务

### 任务 1：平均分为什么不对？

- 位置：`stage1_average()`
- 现象：输出的平均分是 `226.14`，但正确结果应该是 `75.38`
- 要练的技能：**断点 + 单步执行 + 观察变量**

操作建议：

1. 在 `for student in students:` 这一行打断点。
2. 用 Step Over（PyCharm `F8` / VS Code `F10`）走完整个循环。
3. 每一轮都看一下 `total` 和 `count` 的值。
4. 想一想：全班一共 21 个分数，`count` 最后应该是多少？

> 提示：`count` 统计的到底是“学生人数”还是“分数个数”？

---

### 任务 2：程序为什么抛 IndexError？

- 位置：`stage2_top_student()`
- 现象：`IndexError: list index out of range`
- 要练的技能：**异常断点 + 查看调用栈 + 观察循环变量**

操作建议：

1. 开启“异常断点”：
   - PyCharm：`Run` → `View Breakpoints`（`Ctrl+Shift+F8`）→ `+` → `Python Exception Breakpoint` → 勾选 `Any Exception`
   - VS Code：在 `Run and Debug` 面板的 `BREAKPOINTS` 里勾选 `Raised Exceptions`
2. 运行阶段 2：`python 01_调试_demo.py 2`
3. 程序会在抛异常的那一行停下来。
4. 看 `i` 和 `len(students)` 的值，再想想 `range()` 的结束值包不包含。

> 提示：列表下标最大是 `len(students) - 1`。

---

### 任务 3：第二次分组为什么带着第一次的数据？

- 位置：`stage3_group_by_class()`
- 现象：第二次只传入了二班学生，结果里却有一班、三班，二班的名字还重复了
- 要练的技能：**函数调用栈 + Evaluate Expression + 理解默认参数**

操作建议：

1. 在函数第一行 `for student in students:` 打断点。
2. 连续按两次继续（Resume），让函数被调用两次。
3. 第一次和第二次停下来时，分别看 `groups` 的值。
4. 用 Evaluate Expression（PyCharm `Alt+F8`）计算 `id(groups)`，比较两次是否相同。

> 提示：默认参数 `groups={}` 只在函数**定义时**创建一次，
> 之后每次调用都会复用同一个字典。

---

### 任务 4：二分查找为什么会栈溢出？

- 位置：`binary_search()`
- 现象：查找 92 能成功；查找不存在的 100 时抛 `RecursionError`
- 要练的技能：**Step Into + 调用栈 + 条件断点**

操作建议：

1. 在 `mid = (left + right) // 2` 这一行打断点。
2. 第一次先查找 92，用 Step Into（PyCharm `F7` / VS Code `F11`）跟进递归。
3. 观察每次递归后 `left`、`right`、`mid` 怎么变化。
4. 第二次查找 100 时，建议把断点改成条件断点：
   - 条件写成 `target == 100 and left > 15`
   - 这样可以直接跳到出问题的那几层递归，不用按几百次
5. 在调用栈（Call Stack）里上下切换，看看每一层递归的参数。

> 提示：如果某一层递归的区间没有缩小，就会永远递归下去。

---

### 任务 5：为什么有一个不及格的学生被漏掉了？

- 位置：`stage5_remove_failed()`
- 现象：孙八被剔除了，但周九还留在列表里
- 要练的技能：**观察列表变化 + 条件断点 + 理解“边遍历边删除”**

操作建议：

1. 在 `if average < pass_line:` 这一行打断点。
2. 当程序停在孙八这一轮时，用 Evaluate Expression 查看：
   ```python
   [s["name"] for s in students]
   ```
3. 按 Step Over 执行 `students.pop(i)`，再执行 `i += 1`。
4. 再次查看列表，看看周九的下标变成了多少。
5. 也可以把断点条件设为 `student["name"] == "孙八"`，直接停在关键位置。

> 提示：`pop(i)` 之后，后面的元素会整体前移一位。

## 七、进阶玩法

1. **只用命令行调试**：不打开 IDE，试试 Python 自带的 `pdb`。
   ```bash
   python -m pdb 01_调试_demo.py 1
   ```
   常用命令：`l`（看代码）、`n`（下一行）、`s`（进入函数）、
   `p 变量名`（打印变量）、`c`（继续）、`q`（退出）。

2. **先预测，再验证**：每次按 Step Over 之前，先猜一下变量的下一个值，
   再和调试器显示的值对比。这是提升“代码直觉”最快的方法。

3. **只修一个 bug**：每修好一个阶段就单独跑一次该阶段，
   确认输出符合预期后再修下一个，避免多个 bug 互相干扰。

4. **自己加一个阶段 6**：写一个带 bug 的函数（比如统计每个分数段的人数），
   然后让同学或 AI 来调，练习“出题”也是很好的学习方式。
